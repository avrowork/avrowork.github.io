    Mi forma de trabajar (Spec-Driven)

    01

    Spec first

    Antes de implementar, documento el qué y el cómo: criterios de aceptación, contratos de API y casos borde. El PR responde a la especificación, no al revés.

    02

    Tests concurrentes

    Playwright E2E + tests unitarios crecen junto a la feature. Los defectos se detectan antes del code review, no en producción.

    03

    Entrega continua

    Despliegue automatizado al merge en main. Migraciones idempotentes, feature flags cuando la situación lo requiere, y rollback claro ante incidentes.

    04

    Spec diff

    Si el comportamiento cambia, la spec cambia primero. El código refleja únicamente la realidad documentada y trazable.
